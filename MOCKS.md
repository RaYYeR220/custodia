# What is real and what is simulated

A line-by-line account, so nothing here has to be taken on trust.

## Real

| Component | Reality |
|---|---|
| **HydraDB** | The actual engine, `ghcr.io/hydra-db/hydradb:latest`, run from `docker-compose.yml`. No stub, no in-memory substitute, no compatibility shim. Every read and write in this repository is OpenCypher over Bolt against it. |
| **Retrieval** | `algo.MSpaths` / `algo.SSpaths` / `algo.SPpaths` — HydraDB's own path procedures. The `path` field on every evidence item is the hop sequence the engine returned, not one we reconstructed. |
| **The graph** | All system state. Sessions, turns, facts, entities, temporal edges, the answer log and the refusal ledger are vertices and edges in HydraDB. Nothing is mirrored in a second store. |
| **The trust policy** | Runs on every write, in code, before anything can enter a warrant. Not a prompt instruction. |
| **The gate** | The citation checks are Python, executed after the model replies. A model that cites a fact id it was not given fails a dictionary lookup. |
| **The language model** | A real provider over an OpenAI-compatible endpoint (Venice or OpenRouter). Model ids and token counts are recorded per run. |
| **The demo conversations** | Written by hand for this project. They are fiction — there is no real person named Nora — but they are not generated at runtime and not sampled from a benchmark. |
| **The evaluation data** | LongMemEval-S as published, downloaded from Hugging Face, sha256 recorded in `eval/data/manifest.json`. Questions and gold answers are unmodified. |
| **`custodia verify`** | Every line it prints comes from a live query against the running graph at the moment you run it. |

## Simulated, and why

| Component | What it is | Why |
|---|---|---|
| **The poisoning attacks** | Generated by `eval/poison.py` from six templated attack families, with a fixed seed. | There is no public benchmark for memory poisoning. The suite is ours, so its generator, its seed and its full contents are in the repository and re-derivable. It is a construction, not a measurement of attacks seen in the wild. |
| **Attack tiers** | The attack harness declares which channel an injection arrived on. | In production the channel is a fact about the transport. In the harness it is set by the test. That is the honest description: we are testing the policy given a channel, not testing channel attribution. |
| **The demo's `tool` turn** | A shared document that tries to clear an allergy record, written by us. | It is a plausible instance of a real attack class, not a captured incident. |

## Beside the graph, not in it

- **The BM25 index.** HydraDB property values are scalars, so posting lists live in a JSON file
  keyed by vertex id (`data/index/<corpus>.json`). It is rebuilt from the graph and holds no truth
  of its own — delete it and it comes back identical.
- **The response cache.** Content-addressed completions on disk. `demo/cache/` is committed so the
  walkthrough runs with no credentials; a cache hit is exactly the call that would have gone out.

## Not claimed

- No production deployment, no multi-tenant hardening, no access control beyond HydraDB's token.
- No claim that the extractor is state of the art. It bounds everything downstream and its misses
  are visible in the per-type evaluation numbers.
- No claim about attacks outside the six families in `eval/poison.py`.
